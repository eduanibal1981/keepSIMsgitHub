<task>
Fix a money-handling bug in the KeepSIMs backend workers (Node.js, Supabase).

Reported bug: A user buys a premium plan. An auto-refill (scheduled topup) execution later fails due to a PROVIDER issue (e.g., Ding / DTOne / Reloadly / Zendit error). The topup execution ends up marked as `cancelled`/`canceled` in the database, but the money that was debited from the user's wallet for that topup is never refunded. The user loses money on a failed topup.
</task>

<context>
Repo root: the current workspace is the KeepSIMs monorepo. The deployed backend workers live in `servers/` at the repo root:
- `servers/worker_auto_mini_refill.js` — scheduled auto refills (fixed/mini packages)
- `servers/worker_auto_custom_refill.js` — scheduled auto refills (custom amounts)
- `servers/worker_instant_refill.js` — instant refills
- `servers/providers/` — provider client wrappers (ding, dtone, reloadly, zendit)

Money flow (verified from code):
1. Worker claims executions via RPC `claim_due_executions` / `claim_instant_executions` (defined in Postgres, some in `supabase/migrations/*.sql`).
2. Wallet debit happens either inside the claim RPC or via RPC `debit_wallet_for_topup` (see `servers/worker_instant_refill.js` around lines 228-251).
3. On provider success: RPC `update_execution_status` with `p_status: 'success'`.
4. On provider failure: the worker marks `topup_executions` rows `status: 'cancelled'` directly and refunds via RPC `credit_wallet_for_refund` with `p_reference_id: 'refund_exec_' + execution.id` (see failure handlers around `servers/worker_auto_mini_refill.js` lines 410-450, `servers/worker_auto_custom_refill.js` lines 380-420, `servers/worker_instant_refill.js` lines 440-480). There is also an RPC `update_execution_failed`.

Useful reference docs in the repo: `doc/ADD_SIM_PREMIUM_EGYPT_VODAFONE_WORKFLOW.md` (documents the `update_execution_status` RPC contract), `doc/KeepSIMs_database_Scenarios.md` (money path: claim -> debit -> provider -> update status), and the SQL migration `supabase/migrations/20260717080000_c3b2_scheduled_write_rpcs.sql` (schedule cleanup sets `status = 'cancelled'` in several places). The premium plan purchase + wallet purchase migration is `supabase/migrations/20260820000000_j8_premium_plan_pricing_and_wallet_purchase.sql`.

IMPORTANT: the Postgres RPC definitions (`claim_due_executions`, `claim_instant_executions`, `debit_wallet_for_topup`, `credit_wallet_for_refund`, `update_execution_status`, `update_execution_failed`) may NOT all exist in the repo migrations — some were applied directly to the production database.
